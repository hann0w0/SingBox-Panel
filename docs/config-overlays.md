# 导入配置与面板编辑

导入或直接编辑的配置保持可由面板管理。`Server.ConfigOverlay` 保存原始 JSON、导入时的面板输入快照及数组条目与数据库行的关联；`RawConfig` 仍保留最近一次原始文件编辑的内容。

下发时使用当前版本的生成器分别渲染输入快照和当前数据库数据，再把两者的差异合并到原始 JSON。对象按字段递归比较，未变化的字段保留原值，未知字段不依赖白名单。数值使用 `json.Number`，避免改写大整数。删除或停用面板管理的条目会移除该条目；重新启用仍使用原来的身份和原始附加字段。

入站、出站和规则集使用数据库 ID 关联，路由规则使用 ID 或转发记录身份关联。规则导入时记录其原始数组位置，之后不再用位置识别规则。排序只改变可编辑条目的顺序，未知条目保留原有位置之间的相对顺序；新增条目插在其下一个可编辑条目前，无后继时追加到尾部。未知的入站、出站、规则、规则集、服务和 HTTP 客户端作为完整条目保留。

用户自行配置的控制接口和服务保持原样。导入不自动注入统计接口、替换服务或占用新的监听端口。节点在激活完整合并结果前仍执行 `sing-box check`；原始文件编辑失败时恢复之前的快照。

自定义配置对已知标签的引用也参与删除和改名检查。面板不会猜测未知规则的语义来重写它们；仍被自定义内容引用的对象，需要先在配置文件中调整引用。标签和端口校验同时考虑未显示在表单中的入站、出站。

## 扩展表单

新增普通字段时，把字段加入对应的输入模型和生成器即可。输入快照与当前输入都会经过同一个新版生成器，生成器新增的默认值不会被误判为用户修改。用户编辑新字段后，其实际变化会正常覆盖原始值，其他字段继续保留。

输入模型中的新字段必须能通过 JSON 保存和读取；类似路由 `Outbound` 这种排除在普通 JSON 之外的字段，需要单独保存到快照。不要存储静态的旧版渲染结果作为比较基准，也不要重新添加“必须完全重建一致才能编辑”的判断。

新增可编辑条目集合时，需要在 `ConfigProjection.IDs`、原始条目绑定和数组合并路径中注册稳定身份。嵌套对象数组优先使用 `tag`、`name`、`id` 或 `username`；没有稳定身份时，等长数组按位置比较，其他数组作为完整表单字段更新。

数据库迁移 42 为旧的原始模式节点重新建立表单和快照；已管理节点从当前期望配置建立快照，不用可能过期的原始文件覆盖已有表单修改。
